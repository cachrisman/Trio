**Flagged differences (working implementations align vs Trio watch)**

1. **`didDiscover` gating (Trio only):** `guard hasActivePeripheralNameFilter else { _ = emitAttachBlockedIfNeeded(...); return }` (lines 2307–2310). G7SensorKit and DiaBLE do not require an external exact-name filter before attempting attachment from discovery; without `activePeripheralName` set, Trio never calls `connect()` from advertisements — likely consequence: no `didConnect` from the scan path.

2. **`centralManagerDidUpdateState` (Trio only):** requires `connectionState == .scanning` (lines 2248–2249). If `connectionState` is not `.scanning` when Bluetooth becomes `.poweredOn`, Trio skips the retrieve/register/scan recovery path — likely consequence: no scan and no `didConnect` after certain state combinations.

3. **`willRestoreState` restored peripherals (G7SensorKit vs Trio/DiaBLE):** G7 calls `handleDiscoveredPeripheral` for each entry in `CBCentralManagerRestoredStatePeripheralsKey`; Trio only logs key names; DiaBLE only logs `dict`. **Likely consequence:** after state restoration, G7 can re-initiate connection logic; Trio and DiaBLE do not from restored peripheral list (Trio matches DiaBLE here; both differ from G7).

4. **`CBCentralManagerOptionShowPowerAlertKey`:** Trio sets `false`; G7SensorKit and DiaBLE omit it — **possible** difference in system alert behavior when Bluetooth is off (unlikely sole cause of missing `didConnect`).

5. **Scan filter vs broad scan:** Trio and G7 scan with service `[FEBC]`; DiaBLE may use `scanForPeripherals(withServices: nil, options: nil)` — Trio/G7 agree on filtered scan; DiaBLE can differ (still works).

6. **Stop scan before `connect`:** DiaBLE calls `stopScan()` before `connect`; Trio leaves `// central?.stopScan()` commented (line 2185); G7 often keeps scanning until connected/readied. **Possible** radio/stack interaction; not a clean Trio-vs-both agreement.

7. **Watch background modes (in-repo plist):** DiaBLE Watch `Info.plist` includes `UIBackgroundModes` → `bluetooth-central`; merged `Trio Watch App/Info.plist` lists `WKBackgroundModes` → `physical-therapy` only and no `bluetooth-central` in that file — **if** the built watch app does not add `bluetooth-central` elsewhere, Trio could see reduced background BLE behavior vs DiaBLE (verify built `Info.plist`).

8. **Delegate queue:** G7 uses a dedicated serial `managerQueue`; Trio and DiaBLE use main (`queue: nil`) — **possible** timing/reentrancy differences vs G7; DiaBLE matches Trio on main queue.
