# Patch migration and cutover: legacy diffs → mailbox patches (git am) — v3 (big-bang)

This document describes how to convert existing legacy `git apply`-style patch files into **mailbox patches** (generated by `git format-patch`) and cut over the repository so that only the mailbox format is used going forward.

This is a **big‑bang cutover** design:
- During conversion you may temporarily name patches `*.am.patch`
- After conversion and tooling updates are complete, rename to `*.patch`
- After cutover, the legacy patch format is not used anymore

See `feature-branch-workflow-optimization.md` for the day-to-day workflow.

---

## Why migrate?

Mailbox patches + `git am` provide:

- **Provenance:** author, date, commit message
- **Better debugging:** failures map to commits with context
- **Cleaner history during apply:** patch application creates commits

---

## Preconditions (before you start)

- You have a clean local `dev` synced with upstream `dev`.
- You have identified the current patch list and their intended order.
- You are ready to update local tooling and CI patch-apply logic to use `git am`.

---

## Step 1: Sync and create a migration working branch

```bash
git checkout dev
git fetch upstream
git pull origin dev
git merge upstream/dev
git push origin dev

git checkout -b infra/patch-cutover
```

---

## Step 2: Convert each legacy patch into a real commit and mailbox patch

Repeat per patch (keep the numeric ordering stable).

### 2.1 Start from clean base

```bash
git checkout dev
git reset --hard
git clean -fd
git submodule update --init --recursive
```

### 2.2 Apply the old patch and commit it

```bash
git checkout -b tmp/convert-NN dev

git apply --whitespace=fix patches/NN-old-name.patch

git add -A
git commit -m "feat(<scope>): <summary>

<why/notes>

Converted from legacy patch format."
```

### 2.3 Export mailbox patch

```bash
mkdir -p patches
git format-patch -1 --stdout HEAD > patches/NN-new-name.am.patch
```

### 2.4 Verify mailbox patch in disposable worktree

```bash
# Create temporary worktree for verification
TEMP_WT=$(mktemp -d)
git worktree add --detach "$TEMP_WT" dev

cd "$TEMP_WT"
# Configure git identity for git am
git config user.name "Trio Patch Bot"
git config user.email "patch-bot@users.noreply.github.com"

# Apply the patch (this verifies it works)
if git am --3way --keep-cr --whitespace=nowarn "$OLDPWD/patches/NN-new-name.am.patch"; then
  echo "✅ Patch applies successfully"
  # Reset to clean state before removing worktree
  git reset --hard dev
else
  echo "❌ Patch failed to apply"
  git am --abort
  exit 1
fi

cd "$OLDPWD"
git worktree remove --force "$TEMP_WT"
```

### 2.5 Clean up tmp branch

```bash
git checkout dev
git branch -D tmp/convert-NN
```

---

## Step 3: Replace the legacy patch files

For each patch you converted:

- Add the new mailbox patch (`*.am.patch`) to `./patches/`
- Remove the old legacy patch file (`*.patch`) that was `git apply`-style

Do this in a single PR so that the repo never lives in “dual-format forever”.

---

## Step 4: Update patch application tooling (local + CI)

### Local
- Update `scripts/patch-test.sh` to apply mailbox patches using `git am`.
- During cutover, `scripts/patch-test.sh` may temporarily support `patches/*.am.patch`.
- After the final rename, `scripts/patch-test.sh` should use `patches/*.patch` (still mailbox patches applied with `git am`).

### CI (weekly job)
- Update the patch-apply step to use `git am` (not `git apply`).
- Ensure CI is applying patches in deterministic order (numeric prefix).
- Keep the workflow otherwise unchanged.

---

## Step 5: Full stack validation (required)

Use `scripts/patch-test.sh` as the single authoritative validation entry point (it encapsulates the worktree + `git am` apply flow).

```bash
scripts/patch-test.sh
```

If `git am` fails during validation:
- `git am --abort`
- fix code / regenerate patch
- re-run `scripts/patch-test.sh`

## Step 6: Cutover rename (finalize)

Once tooling and CI are fully updated and validated:

```bash
# rename all patches
for f in patches/*.am.patch; do
  mv "$f" "${f%.am.patch}.patch"
done
```

Then update scripts and docs to use `patches/*.patch` as the steady-state glob.

---

## Submodule patches

Patch validation is handled by `scripts/patch-test.sh`, which should run in an isolated worktree and clean up after itself.

This section is only relevant if:
- a patch modifies a submodule’s working tree in a way the test script does not reset, or
- you performed manual debugging steps inside a submodule.

In those cases, restore submodule state after testing:

```bash
git submodule foreach --recursive 'git reset --hard && git clean -fd'
```

During conversion, prefer to keep submodule changes intentional and verify `git am` applies cleanly.

---
## Exit criteria

Cutover is complete when:

- No legacy `git apply`-style patch files remain in `./patches/`
- Tooling uses `git am` (local test + CI weekly apply)
- Patch validation succeeds via `scripts/patch-test.sh`
- A clean-base apply of the full patch stack succeeds
- Local build (`ci/local-build.sh --base-branch dev --build-only`) succeeds
- Release-only upload works from a built IPA (`ci/local-build.sh --release-only`)
